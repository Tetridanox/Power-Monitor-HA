# Power Monitor: инструкция для пользователя

Подключение, показания, настройки и восстановление — по шагам.

Эта инструкция рассчитана на уже собранное устройство с установленной прошивкой. Всё делается кнопками на устройстве, в браузере и в приложениях. Устанавливать программы для разработки и открывать командную строку не нужно. Первую прошивку пустой ESP и подключение силовых проводов выполняет сборщик устройства.

Названия кнопок локальной ESP ниже приведены на **украинском**; рядом при необходимости указан английский вариант. Локальная панель использует UK/EN. В интерфейсе HA доступны язык HA, русский, украинский и английский. Язык сообщений Telegram выбирается отдельно.

<a id="overview"></a>
## 1. Что умеет устройство

**ESP** — маленькая плата внутри Power Monitor. Она собирает показания инвертора и аккумулятора, хранит историю, показывает веб-панель и управляет подключёнными реле по заданным правилам.

**BMS** — контроллер внутри аккумулятора. Он сообщает заряд, ток, напряжение, температуры и состояние отдельных ячеек. Power Monitor получает эти данные по Bluetooth.

| Что с чем соединяется | Для чего |
|---|---|
| Телефон или компьютер → домашний Wi-Fi → ESP | Открыть панель и изменить настройки |
| ESP → инвертор кабелем либо через его Wi-Fi-модуль | Получить показания инвертора |
| ESP → BMS по Bluetooth | Получить показания аккумулятора |
| ESP → интернет → Telegram | Получать уведомления о работе системы |
| Telegram → Home Assistant → бот | Запросить текущие показания и график солнечной генерации |
| ESP → интеграция Power Monitor в Home Assistant | Показания, архив и управление через привязку по коду, без MQTT |
| ESP → домашний MQTT-брокер → Home Assistant | Отдельный вариант MQTT Discovery и датчики Recorder |
| Браузер → интернет → погодный сервис | Показать прогноз солнечной генерации |

Уведомления Telegram с самой ESP работают без Home Assistant. Для команд
`/status` и `/pv` нужны подключённая интеграция Power Monitor, бот в HA и
работающий сервер HA. Для локальной панели не нужна подписка на облачный сервис.

Wi-Fi-сеть **ESP32** — собственная точка доступа устройства. Она нужна для настройки и некоторых Wi-Fi-модулей инвертора. Домашняя сеть и ESP32 — две разные сети.

<a id="first-start"></a>
## 2. Первое подключение и вход

### Если устройство уже подключено к домашнему роутеру

1. Включите Power Monitor и подождите около минуты.
2. Подключите телефон или компьютер к тому же домашнему Wi-Fi.
3. Откройте Chrome, Edge, Safari или другой обычный браузер.
4. В **адресную строку**, где обычно адрес сайта, введите **http://pm.local/**.
5. В окне входа укажите имя пользователя **admin** и пароль, который вам передал сборщик.
6. Дождитесь появления главной страницы и показаний.

Если адрес не открывается: откройте приложение или веб-панель своего роутера → список подключённых устройств → найдите Power Monitor/ESP32 → посмотрите его IP-адрес. Введите в браузере `http://` и этот адрес. Например, `http://192.168.1.50/` — это только пример, у вас адрес будет свой.

### Если домашний Wi-Fi ещё не настроен

1. Включите устройство. Откройте на телефоне **Настройки → Wi-Fi**.
2. Выберите сеть **ESP32**. При отсутствии рабочего соединения с роутером она может появиться примерно через пять минут; при пустых настройках Wi-Fi появляется при запуске.
3. Введите пароль точки доступа, полученный со своим устройством. **После сброса** это `inverter1234`.
4. Если телефон сообщает «В этой сети нет интернета», выберите **Оставаться подключённым / Использовать эту сеть**. При необходимости временно отключите мобильный интернет и VPN.
5. Откройте браузер и введите **http://192.168.4.1/**. Окно настройки может не открыться автоматически — это нормально.
6. Войдите как **admin**. После **полного сброса** пароль — `admin1234`. Сетевой сброс пароль панели не меняет.
7. Настройте домашний Wi-Fi по следующему разделу.

Если вы получили пустую плату без прошивки или без подготовленных реквизитов доступа, передайте её сборщику. Эти шаги не устанавливают прошивку на пустую ESP.

<a id="network"></a>
## 3. Домашний Wi-Fi, пароли и имя

В **мастере первоначальной настройки** выберите сеть и введите пароль,
затем нажмите **«Перезапустити й продовжити» / “Restart and continue”**.
ESP перезапустится; мастер дождётся подключения и откроет шаг **«Инвертор»**.
Подключите телефон/ПК к той же домашней сети;
при смене адреса откройте **http://pm.local/**. Если ESP уже подключена и
ничего не вводилось заново, повторный перезапуск не нужен. Этот порядок общий для
всех моделей, включая Bluetooth настройку логеров.

Если подключение не подтвердилось, мастер остаётся на шаге WiFi. Прошивка
предусматривает защищённую сеть восстановления **ESP32** после пяти минут
отсутствия связи. Когда она появилась, подключитесь к ней с действующим
паролем точки доступа и откройте
**http://192.168.4.1/**; затем выберите доступную домашнюю сеть заново.

### Подключиться к роутеру

1. В меню панели откройте **Налаштування / Settings**. На узком экране сначала раскройте меню.
2. Найдите блок **Мережа та доступ / Network and access**.
3. В **WiFi SSID** впишите точное название домашней сети. Используйте сеть **2,4 ГГц**: ESP32-S3 не подключается к сети только на 5 ГГц.
4. В **Пароль WiFi** впишите пароль этой сети.
5. Нажмите **Зберегти налаштування / Save settings** в этом блоке.
6. Дождитесь сообщения об успешном сохранении. Если нужен перезапуск, нажмите кнопку перезапуска вверху «Налаштування» и затем кнопку подтверждения.
7. Верните телефон в домашний Wi-Fi и снова откройте **http://pm.local/**.

Если меняете роутер, сделайте это до отключения старого, пока панель доступна. После смены сети IP-адрес ESP может измениться.

### Изменить пароли

1. Откройте **Налаштування → Мережа та доступ**.
2. Для входа в панель заполните **Новий пароль вебінтерфейсу**. Имя пользователя остаётся **admin**. Длина пароля — 8–64 символа.
3. Для сети ESP32 заполните **Новий пароль точки доступу**. Длина — 8–63 символа.
4. Нажмите **Зберегти налаштування** и перезапустите ESP.
5. При следующем входе используйте новый пароль. Если браузер повторяет старый, закройте окно входа и откройте панель в приватной вкладке.
6. Если к ESP32 подключён Wi-Fi-модуль инвертора, задайте новый пароль сети и в этом модуле. Иначе он перестанет передавать показания.

Пустое поле нового пароля обычно означает «оставить сохранённый». Для нового Wi-Fi SSID пустой пароль означает открытую сеть. Пустое поле после сохранения само по себе не означает, что пароль пропал.

### Изменить имя

1. В **Налаштування** найдите **Пристрій / Device**.
2. Введите понятное имя, например «Дом».
3. Нажмите именно **Зберегти назву / Save name**.
4. Если появилось сообщение о перезапуске, выполните его.

Имя используется в интеграциях и отчётах, но **не меняет адрес pm.local**. Кнопки сохранения у разных блоков отдельные: сохранение сети не сохраняет новое имя или профиль инвертора.

<a id="inverter"></a>
## 4. Подключение инвертора

Сначала уточните **точную модель** и **способ подключения** у сборщика. Похожее название модели не гарантирует совместимость. Разъём RJ45 у инвертора не обязательно является Ethernet: обычным сетевым кабелем соединять его с роутером нельзя, если это не предусмотрено производителем.

1. Откройте **Налаштування** и блок подключения инвертора.
2. Выберите производителя, затем свою модель и нужный вариант подключения: кабель или Wi-Fi-модуль.
3. Оставьте предложенные параметры профиля, если сборщик не сообщил другие.
4. Нажмите **Підключити / Connect**. Эта кнопка сохраняет профиль.
5. Выполните предложенный перезапуск.
6. Откройте **Інвертор / Inverter**. Проверьте, что появились свежие значения напряжения, нагрузки и солнечной мощности.
7. Сравните несколько показаний с экраном самого инвертора. Учитывайте небольшую задержку обновления.

| Модель | Доступные варианты | Граница поддержки |
|---|---|---|
| EASUN Power SMH3 | RS232 или Solar Plug-RWB1 | Передача показаний проверялась |
| Anern AN-SCI-EVO-3200 | RS232 или Solar Plug-RWB1 | Передача показаний проверялась |
| MUST PV18-3524 ECO | RS485 | Чтение показаний; запись настроек запрещена |
| ANENJI ANJ-4000 | Штатный EyeBond Wi-Fi-даталоггер | Подключение через домашнюю сеть; настройка в мастере |
| Growatt SPF 6000 ES Plus | RS485 expansion или ShineWiFi-F/F Pro | Экспериментальные профили, только чтение; аппаратная проверка не выполнена |

### Если используется Solar Plug-RWB1

Логер и ESP работают через домашнюю сеть Wi-Fi. Настройте её в Power Monitor:

1. Подключите ESP к домашнему роутеру.
2. Откройте мастер, выберите EASUN или Anern → **Solar Plug-RWB1 (WiFi)**.
3. Нажмите **«Найти WiFi-логгер» / “Find WiFi logger”**, выберите свой RWB1.
4. ESP сама прочитает ID и передаст логеру SSID/пароль своей текущей сети.
5. Дождитесь подтверждения свежих данных. При необходимости ESP перезапустится,
   а мастер продолжит проверку автоматически. Приложение Solar of Things не нужно.

Если не удалось подтвердить сеть, откройте **Connection recovery**: проверка
читает параметры без повторной записи, возврат восстанавливает прежний WiFi.
Для ручного подключения раскройте соответствующий раздел: PN берётся в
информации о логере в Solar of Things, IP необязателен для автопоиска.

RWB1 и ESP должны видеть друг друга в сети; изоляция Wi-Fi клиентов может мешать.
Настройки облака сохраняются, открывать порты роутера не нужно.
Идентификатор PN и резервную копию настроек храните в личном защищённом месте.

Для Anenji и Growatt используйте соответствующий отдельный профиль и помощь сборщика. Для ShineWiFi в ShineTools предусмотрен сервер **192.168.4.1**, порт **5279**; этот путь пока экспериментальный. При переходе логгера на локальную ESP облачное приложение производителя может перестать получать данные.

### Настройки самого инвертора

В разделе **Інвертор → Налаштування інвертора** можно изменить рабочие параметры инвертора.

1. Сверьте параметр с инструкцией вашей точной модели.
2. Выберите одно согласованное со сборщиком значение.
3. Нажмите кнопку применения рядом с параметром.
4. Дождитесь результата и повторного чтения. Проверьте значение также на экране инвертора.

Недоступные поля и режим «только чтение» — ограничения конкретного профиля. Не пытайтесь обходить их выбором другой модели. Универсальных безопасных напряжений и токов для всех аккумуляторов нет.

<a id="bms"></a>
## 5. Подключение BMS и схема аккумуляторов

### Подключить первый аккумулятор

1. Включите аккумулятор и его Bluetooth по инструкции производителя.
2. Закройте приложение BMS на телефоне, если оно уже соединено с аккумулятором: одновременное соединение может мешать ESP.
3. Откройте в Power Monitor **Батарея / Battery**.
4. Выберите слот **BMS 1** и нажмите **Знайти BMS / Find BMS**.
5. Дождитесь результатов. Сверьте название и Bluetooth-адрес с наклейкой или приложением аккумулятора.
6. Выберите нужное устройство и нажмите кнопку подключения в его строке.
7. Дождитесь успешного завершения и появления напряжения, заряда и ячеек. Не выбирайте просто первое устройство с сильным сигналом.

Если ничего не найдено: поднесите ESP ближе, проверьте включение Bluetooth и закройте приложение производителя. Фильтр **Лише BMS / BMS only** скрывает посторонние устройства; его можно отключить для проверки. Уже подключённая BMS может не показываться в сканировании.

Для второго аккумулятора повторите шаги в **BMS 2**. Один и тот же Bluetooth-адрес нельзя назначать обоим слотам. Если аккумулятор один, второй слот оставьте свободным.

### Выбрать схему банка

В блоке **Банк → З'єднання АКБ** выберите схему, которая **уже физически собрана**:

| Выбор | Что означает | Как показывается общий банк |
|---|---|---|
| **Паралельно / Parallel** | Аккумуляторы подключены параллельно | Напряжение и SOC усредняются; ток, мощность и ёмкость суммируются |
| **Послідовно / Series** | Аккумуляторы подключены последовательно | Напряжения складываются; SOC и ёмкость ограничиваются меньшим значением |

Нажатие переключателя сохраняет режим расчёта. Оно не переключает физические провода. **При одной доступной BMS панель показывает её данные без удвоения**, даже если выбран последовательный режим. Если одна из двух пропала, отображаемые числа уже не описывают полный банк. Ориентируйтесь также на состояние каждого слота.

### Изменить параметры JK BMS

Для просмотра разблокировка не нужна. Для изменения:

1. Выберите нужный слот BMS и раскройте его подробности.
2. Найдите **Налаштування BMS**.
3. В поле **Пароль для зміни налаштувань** введите пароль вашей BMS, который вы установили в приложении BMS на телефоне.
4. Нажмите кнопку разблокировки рядом с полем.
5. Раскройте нужную группу параметров и измените только согласованное значение.
6. Нажмите кнопку применения **в строке параметра**.
7. Дождитесь сообщения, что значение применено и подтверждено чтением. При тайм-ауте сначала проверьте фактическое значение, а затем решайте, нужен ли повтор.
8. По завершении заблокируйте редактирование.

Это запись в саму BMS. Сброс ESP не отменяет изменения защиты, напряжений или токов, ранее записанные в аккумулятор. Поддержаны не все модели BMS и не все операции; ориентируйтесь на доступные поля и фактическое подтверждение.

В HA недоступны для записи **калибровка напряжения, калибровка тока и аварийный
режим**. Изменяйте только доступные поля и дождитесь подтверждения.
Если время ожидания истекло, сначала обновите значения: BMS могла уже
применить команду.

<a id="readings"></a>
## 6. Как читать показания и историю

### Главная страница

| Обозначение | Простое объяснение |
|---|---|
| **SOC, %** | Оценка оставшегося заряда аккумулятора |
| **V / В** | Напряжение |
| **A / А** | Ток; у батареи положительное значение соответствует заряду, отрицательное — разряду |
| **W / Вт** | Мощность прямо сейчас |
| **kWh / кВт·ч** | Количество энергии за период |
| **Ah / А·ч** | Ёмкость аккумулятора, не энергия за сутки |
| **PV** | Солнечные панели |
| **Grid / Мережа** | Внешняя электросеть |
| **Load / Навантаження** | Потребители на выходе инвертора |
| **≈ … kWh возле батареи** | Приблизительная оставшаяся энергия: ёмкость в А·ч × текущее напряжение ÷ 1000 |
| **—** | Нет подходящего свежего измерения; это не ноль |

Оставшиеся kWh — приблизительная оценка. Из-за потерь, нагрузки и ограничений защиты фактически доступная энергия будет другой. Это не обещание определённого времени работы.

Если BMS недоступна, часть общих показаний может браться из инвертора. Детальные данные ячеек и ёмкости при этом не возникают из ничего. SOC без BMS может быть приблизительным расчётом по напряжению.

В верхней части панели есть индикаторы Wi-Fi, BMS, RAM и времени работы ESP. Нажмите на индикатор, чтобы увидеть детали. RAM — свободная оперативная память; её временное уменьшение при загрузке графиков возможно. Время работы считается с последнего перезапуска.

**Вільно** показывает память сейчас, а **Мінімум з запуску** — сохранённый
минимум с последней загрузки. После завершения нагрузки свободная память
может восстановиться, но исторический минимум останется прежним.

### Графики и архив

1. Откройте **Історія / History**.
2. Выберите доступный диапазон времени у нужного графика.
3. Дождитесь исчезновения кружка загрузки возле заголовка.
4. Наведите указатель или коснитесь графика, чтобы посмотреть значения точки.
5. В нижней части истории нажмите на месяц, чтобы раскрыть суточные итоги.
6. Для выгрузки нажмите **CSV** возле нужного графика. Файл можно открыть в Excel или другом приложении таблиц.

В HA на графике **Поток энергии** по умолчанию включены потоки мощности с
одной шкалой. Для сравнения с напряжением PV или температурой нажмите их
названия в легенде. Подробно их можно посмотреть в режимах **Напряжения** и
**Температура инвертора**. Если измерений за выбранный период нет, лишняя шкала
не появляется. Измеренный ноль и отсутствие данных различаются.

Минутные данные хранятся за последние **7 суток**; отдельный суточный архив вмещает **366 записей дней**. На новом устройстве прошлых данных не будет. ESP накапливает историю самостоятельно — держать браузер открытым для записи не нужно. Всплывающие краткие наблюдения панели и прогноз могут храниться отдельно в конкретном браузере.

CSV графика и резервная копия настроек — разные файлы. Backup настроек не переносит историю. Кнопки полного стирания всей истории в текущей пользовательской панели нет; полный сброс настроек тоже её не стирает.

### Графики на ESP за месяц и год

1. Откройте **Історія → Енергія за місяць і рік** в панели ESP.
2. Выберите **30 днів** или **365 днів**.
3. Выберите солнечную генерацию, импорт из сети, потребление либо заряд/разряд батареи.
4. На годовом графике нажмите месяц, чтобы раскрыть дни. Вернитесь к общему виду кнопкой над графиком.
5. При необходимости сохраните значения кнопкой **CSV**.

Это суточные итоги. Минутная детализация хранится отдельно за последние
7 суток. На телефоне открывается та же панель ESP; постоянно держать телефон
подключённым для записи истории не нужно. Дни без измерений остаются пропусками.
Текущий день ещё не завершён. При наведении на столбец можно посмотреть
количество дней с данными и отметку незавершённого дня.
Над столбцами указана энергия в kWh: `0.00` означает измеренный ноль,
`—` — отсутствие данных. На узком экране проведите по столбцам горизонтально,
чтобы увидеть остальные даты; подписи сохраняют читаемый размер.

### Сравнение солнечного прогноза с фактом

В истории ESP при настроенном **Open-Meteo** доступны часовой прогноз и
фактическая генерация. Синяя линия — прогноз, жёлтая — измеренная средняя
мощность. Раскройте таблицу под графиком, чтобы посмотреть часы и значения.
Пропуск измерений не означает нулевую генерацию.

Наведите указатель или коснитесь графика: вертикальная линия и точки отметят
ближайший час, а подсказка покажет интервал, прогноз и факт в W. При отсутствии
факта будет `—`, без точки на нуле. С клавиатуры перейдите к графику клавишей
Tab, выбирайте часы стрелками, Home/End и закройте подсказку Escape.

Фактическая средняя мощность за час появляется при наличии измерений не менее
чем за 90% этого часа. Под графиком **Факт** и **Прогноз** в кВт·ч сравниваются
за одинаковые измеренные интервалы; это не обязательно весь день.
При обновлении погоды прогноз может меняться. Время графика и суточных
итогов ESP — **Europe/Kyiv**, с переходом на летнее/зимнее время.

Ошибка прогноза за завершённый день появляется, если браузер сохранил прогноз
до начала дня и измерения покрывают не менее 90% дня. Пока таких данных нет,
оценка точности отсутствует. Прогноз не управляет зарядом; его настройка описана
в [разделе 11](#forecast).

<a id="ha-analytics"></a>
### Аналитика батареи в Home Assistant

Откройте **Power Monitor → Аналитика** в верхнем меню панели Power Monitor.
Вкладка появляется при подключении интеграции; отдельные карточки, панели
и ручное редактирование их настроек не нужны.

1. Выберите период **30 дней** или **Год** и нужную **BMS**.
2. Посмотрите общие показатели батареи.
3. В карточке **Динамика батареи** выберите показатель для графика.
4. В карточке **Ячейки** сравните среднее отклонение каждой ячейки за день.
5. Раскройте **Наблюдения балансировки**, чтобы посмотреть отмеченные состояния.

| Показатель | Что означает |
|---|---|
| **SOH, %** | Состояние батареи, сообщаемое самой BMS. Линия 80% служит ориентиром и не предсказывает дату отказа |
| **Циклы** | Счётчик циклов из BMS |
| **ΔV max, mV** | Максимальный наблюдавшийся разброс между самой высокой и самой низкой ячейкой за выбранный период |
| **Отклонение от среднего, mV** | Насколько среднее напряжение ячейки за день отличалось от остальных. Цвет помогает заметить отличие |
| **Балансировка** | Наблюдавшееся состояние балансировки; короткое переключение между проверками может не попасть в журнал |

HA начинает накапливать эту историю после подключения, когда доступно чтение
показаний и данных BMS. Проверка выполняется раз в 5 минут. Старую поячеечную
историю до подключения HA восстановить нельзя. При замене батареи показания
разных аккумуляторов не склеиваются в одну кривую.

Показывается столько ячеек, сколько сообщает BMS. Пропущенное измерение — «—».
Карта ячеек показывает последние 31 день выбранного периода. Разброс напряжений
зависит также от заряда, тока и температуры: один цветной день сам по себе не
доказывает неисправность ячейки.

<a id="ha-prices"></a>
### Цены и оценка расходов

1. В **Аналитике** найдите карточку **Энергия и стоимость** и нажмите **Тарифы**.
2. Выберите **Одна цена** или **День / ночь**.
3. Укажите цену за кВт·ч и валюту, например **UAH**. Для дня/ночи заполните обе цены и часы ночного тарифа.
4. Оставьте часовой пояс **Как в Home Assistant**. Другой пояс можно выбрать в списке **Дополнительно**, если место установки отличается от настроек HA.
5. Нажмите **Сохранить**. Кнопка **Отмена** закрывает окно без изменения цен.

Цены можно изменить в любой момент. Они применяются ко всему выбранному
периоду; история прежних цен поставщика не ведётся. При тарифе день/ночь
расчёт использует только сохранившиеся минутные измерения. **Покрытие
измерениями** показывает, сколько времени учтено: пропущенные часы не
считаются бесплатной энергией.

Стоимость солнечной генерации — оценка по указанной цене, а не измеренная
экономия на счёте поставщика. Настройки цен сохраняются в HA и не меняют
работу реле, зарядного устройства или ночного контроллера ESP.
Отдельная штатная панель **Энергия HA** подключается по [разделу 8](#ha-energy).

### Открывать панель с главного экрана телефона

Откройте панель в браузере и выберите в его меню **Добавить на главный экран**
или **Установить приложение**, если такой пункт доступен. Полная установка
приложения и открытие сохранённой оболочки без сети требуют адреса **HTTPS**,
подготовленного администратором. Обычный адрес **HTTP** ESP позволяет сделать
ярлык. Без связи с ESP нет свежих показаний и выполнения команд.

### Журнал событий

1. Откройте **Події / Events**.
2. Выберите нужные категории и нажмите **Оновити / Refresh**, если требуется.
3. Чтобы удалить записи журнала, нажмите **Очистити журнал** и подтвердите действие.

Очистка журнала удаляет события, но не настройки и не графики энергии. Если собираетесь обращаться за помощью, сначала сохраните нужные сведения.

<a id="telegram"></a>
## 7. Telegram: уведомления, команды и графики

Бот Power Monitor используется для уведомлений о работе системы и отправки отчётов.

### Шаг 1. Создать своего бота

1. Откройте Telegram и перейдите к официальному **[BotFather](https://t.me/BotFather)**.
2. Нажмите **Начать / Start**.
3. Отправьте сообщение **/newbot** — это сообщение в Telegram, не командная строка компьютера.
4. В ответ на первый вопрос напишите название, например «Энергия дома».
5. В ответ на следующий вопрос придумайте свободное имя латиницей, заканчивающееся на **bot**.
6. BotFather пришлёт ссылку на созданного бота и **токен** — длинную строку с двоеточием. Скопируйте токен целиком.
7. Откройте своего нового бота по ссылке и нажмите **Начать / Start**.

Токен — ключ управления ботом. Вставляйте его только в свою панель ESP; не отправляйте помощникам для определения ID. Порядок создания описан также в [официальной инструкции Telegram](https://core.telegram.org/bots/tutorial).

### Шаг 2. Узнать свой Chat ID

1. В Telegram откройте **[@id_bot](https://t.me/id_bot)**.
2. Нажмите **Начать** или отправьте обычное сообщение.
3. Скопируйте число из поля **ID** в ответе.

Это сторонний бот: ему не нужен токен вашего бота или пароль ESP. Такой способ указан в [документации Home Assistant](https://www.home-assistant.io/integrations/telegram_bot/#create-a-bot-in-telegram). Если сервис недоступен, попросите сборщика помочь получить ID.

### Шаг 3. Заполнить Telegram в ESP

1. Откройте панель ESP → **Telegram**.
2. Включите общий тумблер **Увімкнути інтеграцію Telegram**.
3. В **Bot Token** вставьте токен из BotFather.
4. Нажмите кнопку добавления получателя — **Додати отримувача**.
5. В поле имени напишите, например, «Я».
6. В **Chat ID** вставьте число из предыдущего шага.
7. Включите **Увімкнути профіль**.
8. Отметьте нужные события. Для тестового сообщения включите **Мережу відновлено** у получателя.
9. При необходимости включите **Щоденний звіт**, **Тижневий звіт** и **Зміна стану реле**.
10. Выберите язык сообщений и час ежедневного отчёта. Значение `20` означает 20:00.
11. Нажмите **Зберегти налаштування**, затем перезапустите устройство через **Налаштування**, чтобы изменения вступили в силу.
12. Вернитесь в **Telegram** и нажмите **Тестове повідомлення**.
13. Проверьте, что сообщение действительно пришло в Telegram. «Добавлено в очередь» ещё не означает «доставлено».

Для другого человека повторите получение его личного ID, попросите его нажать **Start у вашего бота**, добавьте отдельного получателя и сохраните. Поддерживается до **10 профилей**. Профиль можно выключить, сохранив его данные.

Чтобы полностью остановить Telegram, выключите общий тумблер, сохраните
настройки и перезапустите ESP. После загрузки Telegram не создаёт фоновую
задачу, очередь и HTTP-клиент и не обрабатывает уведомления или отчёты. Токен и
получатели сохраняются для последующего включения. Выключение отдельного профиля
останавливает сообщения только этому получателю и не выключает службу целиком.

### Уведомления и очередь

Порог низкого заряда задаёт момент предупреждения; порог восстановления должен быть выше него, чтобы сообщения не повторялись около одной границы. Сообщение о полном заряде учитывает одновременно SOC, небольшой ток и время подтверждения. Эти настройки меняют уведомления, а не зарядное устройство.

У каждого получателя свои подписки. Уведомление о реле по умолчанию выключено. Оно сообщает изменение команды реле и не подтверждает подачу напряжения на нагрузку.

Внизу страницы видны результаты отправок. **Очистити чергу / Clear queue** удаляет ожидающие отправки; используйте её, только если больше не нужны накопившиеся уведомления. Это не удаляет сообщения из Telegram.

<a id="telegram-commands"></a>
### Команды и графики через Home Assistant

**Команды работают только при подключённой интеграции Home Assistant и
включённом сервере HA.** ESP продолжает самостоятельно отправлять свои уведомления,
если они включены; обработкой команд занимается HA.

1. Подключите своего бота через **Настройки HA → Устройства и службы →
   Telegram bot**, выбрав Polling или Webhooks, и добавьте разрешённый чат.
2. Откройте **Power Monitor → Управление → Telegram → Команды и графики**.
3. Выберите бота, чат, язык сообщений и период графика в часах.
4. Включите нужные команды и нажмите **Сохранить**. Дополнительная автоматизация
   и редактирование YAML не требуются. Если раньше использовали blueprint
   Power Monitor для этих команд, отключите старую автоматизацию.

Для обычной домашней установки выбирайте **Polling**: HA сам получает команды
из Telegram. Для Webhooks нужен заранее настроенный доступ к HA извне.
Режим **Broadcast** только отправляет сообщения и для команд не подходит.
Подключение бота описано в
[официальной инструкции HA](https://www.home-assistant.io/integrations/telegram_bot/).
Можно использовать того же бота, что отправляет уведомления ESP: команды
принимает HA, а уведомления ESP продолжают настраиваться отдельно.

| Команда | Что придёт в чат | Как проверить |
|---|---|---|
| `/status` | Текст: доступность инвертора и BMS, SOC, мощность солнца, сети, нагрузки и батареи | Сравните с текущими показаниями Power Monitor. При потере связи значение может быть недоступно |
| `/pv` | Картинка измеренной солнечной мощности за выбранное число часов | Сравните с историей PV в HA; это фактическая генерация, а не прогноз |

Период графика задаётся в форме: от **1 до 168 часов**, обычно 24 часа.
Время соответствует часовому поясу HA. Нулевая генерация ночью ожидаема;
отсутствующие измерения не превращаются в нулевую генерацию.
В личном чате отправитель определяется автоматически; для группы укажите
ID одного разрешённого отправителя. Настройки сохраняются в HA.
Уведомления самой ESP находятся в свёрнутом блоке ниже и настраиваются отдельно.

Для проверки напишите боту `/status`, затем `/pv`. Если ответа нет, проверьте
работу HA, выбранного бота, разрешённый чат и переключатель нужной команды.
Кнопка теста уведомлений ESP проверяет другой путь и не проверяет команды HA.

<a id="ha"></a>
## 8. Home Assistant: подключение и работа

### Вариант A. Интеграция Power Monitor по коду

Для показаний, собственного архива, графиков и управления используйте
**Power Monitor**. MQTT для этого варианта включать не требуется.

Перед установкой проверьте, что панель ESP открывается по её IP-адресу,
показания обновляются, а HA и ESP доступны друг другу в локальной сети.
Гостевая Wi-Fi-сеть и изоляция клиентов могут препятствовать подключению.
Нужны права администратора HA и совместимая версия HA, указанная в
[описании актуального релиза](https://github.com/Tetridanox/Power-Monitor-HA/releases/latest).
Перед обновлением существующей установки сделайте резервную копию HA.

1. В уже установленном **HACS → Пользовательские репозитории** добавьте
   [Tetridanox/Power-Monitor-HA](https://github.com/Tetridanox/Power-Monitor-HA),
   категория **Integration**.
2. Скачайте **Power Monitor** и перезапустите Home Assistant.
3. На ESP откройте **Home Assistant**, включите прямую интеграцию и нажмите
   **«Отримати код на 2 хвилини»**. Код содержит доступ к устройству:
   не публикуйте его и не присылайте в общий чат.
4. В HA откройте **Настройки → Устройства и службы → Добавить интеграцию →
   Power Monitor**, вставьте код в течение двух минут.
5. Откройте **Power Monitor** в боковом меню. ESP и HA должны видеть друг друга
   в локальной сети. Проверьте, что мощность и состояние связи обновляются.

Если HACS ещё не установлен, его установку выполняет администратор HA.
Пункт добавления репозитория находится в меню с тремя точками HACS:
[официальная инструкция HACS](https://www.hacs.dev/docs/faq/custom_repositories/).
При обновлении через HACS перезапустите HA и полностью перезагрузите страницу
браузера. Если показания есть, а управление недоступно, выберите
**Перенастроить** и подключите устройство по новому коду. Архив сохранится.

### Установка вручную без HACS

1. Скачайте архив `power-monitor-ha-…zip` из
   [релизов интеграции](https://github.com/Tetridanox/Power-Monitor-HA/releases).
2. Откройте папку конфигурации HA — ту, где находится `configuration.yaml`.
   Способ доступа зависит от установки HA: файловый редактор, сетевой ресурс
   или каталог, подключённый к контейнеру.
3. Из архива перенесите папку `custom_components/power_monitor_archive`
   в одноимённый путь внутри конфигурации HA. Файл `manifest.json` должен
   лежать непосредственно в `custom_components/power_monitor_archive`,
   без дополнительной вложенной папки архива.
4. Перезапустите HA. Добавьте интеграцию и получите код на ESP, как описано выше.

При ручном обновлении заменяйте папку кода целиком. Старую копию храните
за пределами `custom_components`, чтобы HA не пытался загрузить её второй раз.
Сохраняйте `.storage`, базы архива и свой дашборд. Удалять интеграцию из HA
ради обычного обновления не требуется.

### Проверка после подключения или обновления

Откройте **Обзор** и убедитесь, что текущие данные приходят. В диагностике
сверьте версию ESP, затем откройте **Историю** и дождитесь синхронизации.
Чтобы проверить доступ к управлению без включения нагрузки, откройте
настройки реле и закройте окно кнопкой отмены.

Если HACS не показывает новый релиз, выберите **Обновить информацию**
в меню репозитория. После установки обновления перезапустите HA.
Если остался прежний вид карточек, полностью перезагрузите страницу
или закройте и снова откройте приложение HA. Не удаляйте архив и интеграцию
для очистки браузерного кеша.

Первая загрузка пяти дополнительных карточек требует доступ HA к GitHub;
затем они хранятся локально. Дашборд создаётся при открытии HA под
администратором. Его можно редактировать: обновление не заменяет ваш YAML.
Повторная кнопка создания открывает существующий дашборд.

В **Управлении** доступны реле, инвертор, BMS, настройки, Telegram,
Home Assistant/MQTT и события. Запись требует права администратора HA,
а экспертные настройки инвертора и BMS — отдельной временной разблокировки.
После закрытия карточки/истечения срока разблокируйте заново.
В диагностике время работы показано в **днях, часах и минутах**.

Архив хранится на диске HA отдельно от Recorder и доступен при выключенной ESP.
Включайте его в резервную копию HA. Расчётная ёмкость ESP — 7 суток минутных
точек и 366 суточных итогов. На ранее заполненном хранилище старая часть
минутной истории может быть короче; ориентируйтесь на реально доступные даты,
а не на обещание полного окна. Данные, которые уже вышли из доступного окна
за время отключения HA, догрузить нельзя. HA архив не импортируется автоматически
в стандартную панель «Энергия».

В **Управление → Подключение** можно выбрать обычную страницу ESP или HA.
Для полного локального интерфейса всегда остаётся адрес
`http://<IP-ESP>/local/`. Выбор HA не отключает ESP и запись истории.
Язык управления выбирается в заголовке; введённые значения сохраняются
при переключении языка и внутренних вкладок.

### Где искать функции в Power Monitor

Верхнее меню панели содержит вкладки; на небольшом экране они могут быть
показаны только значками. Наведите указатель или откройте вкладку, чтобы
посмотреть её заголовок.

| Вкладка | Для чего открывать | Что можно сделать |
|---|---|---|
| **Обзор** | Текущее состояние системы | Посмотреть потоки мощности, заряд, суточную энергию и солнечный прогноз |
| **Диагностика** | Подробности батарей | Выбрать BMS, сравнить ячейки, напряжения, температуры и состояние связи |
| **Управление** | Изменение параметров | Настроить реле, инвертор, BMS, подключение, Telegram, MQTT; сохранить копию или обновить ESP |
| **История** | Измерения за выбранное время | Выбрать период и показатель, включить линии в легенде, посмотреть значения и скачать CSV |
| **События** | Причины изменений и неполадки | Посмотреть журнал, выбрать события и сохранить нужные записи |
| **Аналитика** | Длительное наблюдение и стоимость | Выбрать BMS и период, сравнить состояние ячеек, открыть тарифы и оценку расходов |

Аналитика уже встроена в панель интеграции. Создавать отдельный дашборд или
добавлять её в настройки не требуется. Штатная **Энергия** находится отдельно
в боковом меню HA: она объединяет учёт разных устройств вашего дома.

### Посмотреть историю в HA и сохранить график

1. Откройте **Power Monitor → История**.
2. Выберите период и режим: потоки мощности, напряжения, SOC или температуру.
3. Нажмите название линии в легенде, чтобы включить или скрыть её.
4. Наведите указатель на график либо коснитесь его на телефоне: появятся время и значения.
5. При необходимости увеличьте нужный участок графика доступными жестами или органами масштаба. Для возврата выберите исходный период.
6. Нажмите **CSV**, чтобы сохранить измерения для таблицы.

Мощность, напряжение и температура имеют разные единицы. На общем графике
дополнительные оси появляются при включении соответствующих линий.
Скрытие линии меняет отображение; сохранённые измерения остаются в архиве.
История Power Monitor и статистика штатной «Энергии» хранятся отдельно.

### Штатная «Энергия» HA: что показывает и как настроить

Эта панель отвечает на вопросы «сколько энергии пришло из сети», «сколько
выработали панели» и «сколько прошло через батарею». Она использует статистику
HA. Панель Power Monitor с её историей и аналитикой доступна независимо от
того, настроена ли штатная «Энергия».

#### Шаг 1. Открыть настройки и найти датчики

1. Войдите в HA под администратором.
2. Откройте **Энергия** в боковом меню. При первом открытии появится мастер настройки.
3. Если панель уже настроена, нажмите **карандаш в правом верхнем углу**.
   Другой путь: **Настройки → Панели управления → Энергия**.
4. В списках ищите сущности устройства Power Monitor. Если устройств несколько,
   выберите нужное по имени, а не только по названию показателя.

Для энергии нужны датчики в **кВт·ч / kWh**, а для мощности — в **Вт / W**.
Например, **Из сети сегодня** — накопленная энергия, а **Из сети** — мощность
сейчас. Это разные поля. Датчики с названием «сегодня» обнуляются с началом
нового дня; HA учитывает такой переход при накоплении статистики.

#### Шаг 2. Добавить электрическую сеть

1. В разделе **Электрическая сеть** нажмите **Добавить подключение к сети**.
2. В поле **Импортируемая из сети энергия** выберите **Power Monitor · Из сети сегодня**, единица **kWh**.
3. Поле **Экспортируемая в сеть энергия** оставьте пустым: Power Monitor не предоставляет отдельный счётчик отдачи в сеть.
4. Для текущей мощности выберите тип **Стандартный** и датчик **Power Monitor · Из сети**, единица **W**.
5. При желании задайте понятное название, например **Сеть**.
6. Выберите способ учёта стоимости по инструкции ниже и сохраните подключение.

Здесь учитывается энергия, которую видит Power Monitor в своём подключении
к инвертору. Если часть дома подключена мимо инвертора, она не становится
измеренной нагрузкой Power Monitor. Для полного учёта дома нужен отдельный
общий счётчик с корректно настроенной схемой учёта.

#### Шаг 3. Добавить солнечные панели

1. В разделе **Солнечные панели** нажмите **Добавить источник**.
2. В поле **Энергия, получаемая от солнечных панелей** выберите
   **Power Monitor · Солнечная энергия сегодня**, **kWh**.
3. В поле **Мощность генерации** выберите **Power Monitor · Солнечная генерация**, **W**.
4. Для начала оставьте **Не прогнозировать генерацию** и сохраните источник.

Прогноз Power Monitor не подключается к этому полю автоматически. Если нужен
прогноз именно в штатной «Энергии», подключите совместимую интеграцию прогноза
HA и выберите её здесь. Для прогноза в панели Power Monitor используйте
[раздел 11](#forecast).

#### Шаг 4. Добавить аккумуляторную батарею

1. В разделе **Аккумуляторная батарея** нажмите **Добавить батарею**.
2. Заполните поля по таблице и сохраните.

| Поле HA | Датчик или значение | Смысл |
|---|---|---|
| **Энергия, поступающая в батарею** | **Power Monitor · Заряд батареи сегодня**, kWh | Сколько энергии поступило на заряд |
| **Энергия, поступающая из батареи** | **Power Monitor · Разряд батареи сегодня**, kWh | Сколько энергии отдала батарея |
| **Сенсор уровня заряда батареи** | **Power Monitor · Заряд батареи**, % | Текущий SOC; не путайте с энергией заряда за день |
| **Тип измерения мощности** | **Инвертированный** | У Power Monitor положительная мощность означает заряд, отрицательная — разряд |
| **Мощность батареи** | **Power Monitor · Мощность батареи**, W | Нужна для отображения текущего потока |
| **Емкость батареи** | Полезная ёмкость банка в kWh, если она известна | Не вводите сюда ёмкость в Ah. Поле полезно при нескольких батареях для общего SOC |

Общие датчики Power Monitor описывают весь настроенный банк. Не добавляйте
тот же банк повторно как две батареи, подставляя одинаковые счётчики для BMS 1
и BMS 2. **Оставшаяся энергия банка** — запас на данный момент, поэтому она
не подходит вместо счётчика заряда или разряда.

После сохранения проверьте стрелки во вкладке **Сейчас**: при реальном заряде
поток должен идти **в батарею**, при разряде — **из батареи**. Если направление
обратное, проверьте выбранный тип мощности и порядок двух счётчиков.

#### Шаг 5. Выбрать учёт стоимости

Откройте созданное подключение **Сеть → Отслеживание затрат**.

| Вариант HA | Когда выбирать | Что заполнить |
|---|---|---|
| **Не отслеживать расходы** | Нужны только графики и kWh | Цену вводить не нужно |
| **Использовать фиксированную цену** | Одна цена за kWh | Вашу цену за 1 kWh; валюту проверьте в основных настройках HA |
| **Использовать объект с текущей ценой** | В HA уже есть датчик цены, например меняющий цену день/ночь | Существующий датчик цены с правильной валютой и единицей за kWh |
| **Использовать объект, отслеживающий общие расходы** | Другой прибор или интеграция уже считает денежные расходы | Существующий накопительный датчик стоимости |

Для обычного тарифа с одной ценой достаточно второго варианта. Для дня/ночи
штатной «Энергии» нужен отдельно настроенный источник текущей цены или
тарифного учёта HA; одной записи двух чисел в Power Monitor для этого мало.

Цены в **Power Monitor → Аналитика → Тарифы** и цены штатной **Энергии**
настраиваются отдельно. Автоматической синхронизации между ними нет.
Аналитика пересчитывает выбранный период по своим ценам; штатная «Энергия»
ведёт собственную статистику расходов. Не рассчитывайте, что изменение цены
в одном окне изменит старые расходы в другом.

#### Шаг 6. Проверить результат и выбрать период

1. Вернитесь в **Энергия**. Первые итоги появляются после обработки статистики HA;
   сразу после установки накопленных данных может ещё не быть.
2. Во вкладке **Сводка** посмотрите **Распределение энергии** и таблицу **Всего**:
   сеть, солнце, заряд и разряд должны соответствовать вашей схеме.
3. Во вкладке **Электроэнергия** посмотрите графики за период и доступные сведения о расходах.
4. Во вкладке **Сейчас** проверьте текущие потоки; для них нужны добавленные датчики мощности.
5. Внизу экрана нажмите на дату/период и выберите день, месяц, год или другой
   доступный диапазон. Стрелки переходят к предыдущему и следующему периоду;
   **Текущий период** возвращает к текущей дате.

**kWh** на схеме за выбранный месяц — сумма за месяц, а **W / kW** на графике
«Источники питания» — мощность в конкретный момент. У этих графиков разный
смысл. В таблице **Всего** батарея показывает разряд минус заряд. Например,
заряжено 8,38 kWh, отдано 6,70 kWh — итог **−1,68 kWh**: в течение периода
батарея получила больше, чем отдала. Разница связана с изменением запаса и
потерями; это не отрицательный счёт за электричество. Разряд за период может
превышать заряд, если батарея была заряжена до начала этого периода.

#### Что ещё можно настроить

- Переименовать источники, изменить выбранные датчики, цену, SOC и полезную
  ёмкость — через карандаш настройки «Энергии».
- Добавить отдельные приборы в **Потребители энергии**, если для каждого есть
  свой датчик энергии. Одно реле Power Monitor измерение kWh не создаёт.
- Добавить другие системы дома: отдельный солнечный инвертор, счётчики воды
  или газа, если они уже подключены к HA. Power Monitor этих датчиков не создаёт.

Не добавляйте **Потребление сегодня** всего инвертора как отдельный бытовой
прибор: этот показатель уже описывает общую нагрузку его выхода. Для одной
физической цепи выбирайте один источник измерений; повторное добавление того
же потока через MQTT и прямую интеграцию даст двойной учёт.

#### Как показать более ранние дни из архива Power Monitor

Обычные датчики HA начинают собирать статистику после подключения. Старые
дни из архива Power Monitor автоматически в штатную «Энергию» не переносятся.
Для просмотра этих дней без дополнительных действий используйте
**Power Monitor → История**.

Для переноса суточных итогов в «Энергию» предусмотрено действие
**Preview or export daily archive to HA Energy statistics** в
**Инструменты разработчика → Действия**. Эту дополнительную настройку выполняет
администратор: выбирает идентификатор Power Monitor, сначала оставляет
**dry_run** включённым для предпросмотра и задаёт границу **до начала суток,
с которых уже есть текущая статистика HA**. При подтверждении импорта
используется `IMPORT_DAILY_ARCHIVE`.

В обычных настройках панели кнопки этого импорта нет; это служебное действие
администратора. Оно не требуется для накопления новых дней в «Энергии».

Импорт создаёт отдельные архивные источники. Их выбирают в настройках
«Энергии» для соответствующих потоков, соблюдая одну границу архива и текущих
измерений. Уже импортированные точки не перезаписываются, выбранную границу
потом нельзя произвольно сдвигать. Если администратор уже настроил архив,
повторять импорт для обычного просмотра не нужно.

Импорт переносит итог за день, но не восстанавливает часы и мощность внутри
этого дня. Поэтому месячный график kWh может содержать старые дни, а график
мощности — только даты после подключения HA. Почасовые столбцы старого архива
не показывают реальное распределение потребления по часам. Для такого архива
не назначайте фиксированную цену или датчик текущей цены: отдельная денежная
статистика из Power Monitor не экспортируется.

#### Если датчика нет или итог выглядит неверно

1. Проверьте **Настройки → Устройства и службы → Power Monitor → Устройство**:
   нужная сущность должна быть включена и иметь свежее значение.
2. Сверьте единицы: счётчики энергии — **kWh**, мощность — **W**, SOC — **%**.
3. Попросите администратора проверить запись этих датчиков в Recorder и ошибки
   в **Инструменты разработчика → Статистика**. Архив Power Monitor не заменяет Recorder.
4. Если нет только старых дней, проверьте дату начала сбора и наличие
   дополнительного импорта. Перезапуск HA сам по себе старые дни не добавит.
5. При завышенных итогах проверьте дубли источников и пересечение архива с
   текущими измерениями; при неверных стрелках батареи — направление мощности.

Дополнительные сведения: [настройка сети в HA](https://www.home-assistant.io/docs/energy/electricity-grid/),
[энергия, мощность и поиск отсутствующих датчиков](https://www.home-assistant.io/docs/energy/faq/).

### Вариант B. MQTT Discovery

Это независимый способ подключения датчиков и MQTT автоматики. Его можно
использовать вместе с вариантом A. Показания двух способов могут появиться
как разные сущности; выбирайте нужный источник для своих автоматизаций.

Ниже — путь для уже работающего **Home Assistant OS** с магазином приложений. **MQTT-брокер** — небольшое приложение-посредник между ESP и Home Assistant. Если брокер уже настроен, не создавайте второй: получите у администратора его адрес, порт, имя пользователя и пароль.

### Шаг 1. Установить Mosquitto broker

1. В Home Assistant откройте **Настройки → Приложения → Установить приложение**. Этот раздел также может называться **Дополнения → Магазин дополнений**.
2. Найдите **Mosquitto broker** и нажмите **Установить**.
3. Включите запуск при загрузке и нажмите **Запустить**. Дождитесь запуска.

Если пункта «Приложения/Дополнения» нет, возможно, Home Assistant работает в контейнере. Установку брокера в таком случае поручите администратору; после этого продолжайте с готовыми реквизитами. [Приложения Home Assistant](https://www.home-assistant.io/apps).

### Шаг 2. Создать пользователя MQTT

1. Откройте **Настройки → Люди → Пользователи**.
2. Если вкладки нет, откройте свой профиль внизу бокового меню и включите **Расширенный режим**.
3. Добавьте пользователя, например **power_monitor**, и задайте отдельный пароль. Права администратора ему не нужны.
4. Запишите имя и пароль для ввода в ESP.

### Шаг 3. Подключить MQTT к Home Assistant

1. Откройте **Настройки → Устройства и службы → Интеграции**.
2. На найденной карточке **MQTT** нажмите **Настроить / Добавить** и завершите предложенные шаги.
3. Если карточка не появилась, нажмите **Добавить интеграцию**, найдите **MQTT**, укажите адрес брокера, его порт и учётные данные.

Шаги установки и пользователя основаны на [официальном руководстве Mosquitto](https://github.com/home-assistant/addons/blob/master/mosquitto/DOCS.md), подключение интеграции — на [документации MQTT](https://www.home-assistant.io/integrations/mqtt/). Названия кнопок зависят от языка интерфейса и способа установки HA.

### Шаг 4. Заполнить Home Assistant в ESP

1. В панели Power Monitor откройте **Home Assistant**.
2. Включите **Увімкнути інтеграцію**.
3. Заполните поля по таблице.

| Поле ESP | Что указать |
|---|---|
| **Адреса MQTT-брокера** | IP компьютера/устройства, где запущен Mosquitto. Если это приложение HA, IP устройства с HA. Например `192.168.1.20`, без `http://`, без `:8123` |
| **Порт** | `1883` для обычного локального Mosquitto |
| **Транспорт MQTT** | `tcp` для этого примера |
| **Користувач MQTT** | Созданное имя, например `power_monitor` |
| **Пароль MQTT** | Пароль этого пользователя |
| **Префікс MQTT Discovery** | `homeassistant`, если администратор не менял его |

4. Пока оставьте **Дозволити керування нічним тарифом** выключенным.
5. Нажмите **Зберегти налаштування** и выполните требуемый перезапуск ESP.
6. Откройте этот раздел снова. Дождитесь **підключено / Connected** и завершения публикации сущностей. Это может занять около минуты.
7. В Home Assistant откройте **Настройки → Устройства и службы → MQTT → Устройства**.
8. Найдите устройство по заданному имени; отдельно могут появиться диагностические устройства BMS 1 и BMS 2.
9. Откройте несколько датчиков и убедитесь, что значения обновляются, а не просто присутствуют в списке.

Не вводите адрес самой ESP, адрес сайта удалённого доступа HA или внутреннее имя контейнера `core-mosquitto` в ESP вместо доступного локального адреса брокера. Порт **8123** относится к веб-панели HA, а не к MQTT.

### Шаг 5. Добавить показания на панель HA

1. В HA откройте нужную панель → меню редактирования → **Редактировать панель**.
2. Нажмите **Добавить карточку** и выберите карточку сущностей или датчика.
3. Найдите датчики Power Monitor: заряд батареи, мощность нагрузки, PV и другие нужные значения.
4. Добавьте их и нажмите **Сохранить / Готово**.

Общие SOC, ток, напряжение и ёмкость описывают **банк целиком**. BMS 1/BMS 2 предназначены для диагностики отдельных аккумуляторов. Если второй аккумулятор отсутствует, его недоступные датчики ожидаемы. Счётчик публикации в ESP включает служебную очистку старых записей и не обязан совпадать с числом видимых датчиков.

### Управление тарифом и ограничения

Когда локальный ночной тариф уже настроен и проверен, можно включить **Дозволити керування нічним тарифом**, сохранить и при необходимости перезапустить ESP. В HA появятся дополнительные органы управления тарифом. Они реально меняют настройки ESP.

Обычный локальный MQTT на 1883 не шифруется; используйте его в своей доверенной домашней сети. Для готового брокера с TLS получите у администратора имя сервера, порт и параметры доверенного сертификата; в ESP поддержаны `auto`, `tcp`, `tls`. Простая смена порта на 8883 сама по себе TLS не настраивает. ESP не является ESPHome-устройством: для этого подключения используется MQTT.

<a id="relays"></a>
## 9. Реле

Реле управляет подключённой нагрузкой. Настройка зависит от схемы, полярности входа модуля и того, что подключено к контактам. Силовое подключение должен проверить специалист. Нажатие ON может немедленно включить нагрузку.

1. Откройте **Реле / Relays** и вкладку каналов реле.
2. Нажмите кнопку настроек справа в карточке нужного канала, сверив номер с маркировкой проводов. Настройки откроются в окне по центру.
3. Укажите понятное имя нагрузки.
4. Проверьте **Логіка входу / Active LOW или Active HIGH** по вашему модулю. Не подбирайте её наугад. GPIO закреплён за каналом и в форме не меняется.
5. Выберите, должен ли канал быть включён в работу.
6. Для автоматической работы задайте условия запуска, остановки и расписание. Значения согласуйте под вашу нагрузку.
7. Нажмите **Зберегти** внизу окна. **Скасувати**, крестик или Escape закроют окно без сохранения введённых изменений.
8. Выберите рабочий режим **Авто**, **Увімкнено** или **Вимкнено** на карточке и проверьте состояние и строку **Причина**.

Причина объясняет текущее состояние: например, **Увімкнено вручну**,
**Вимкнено вручну** или **Зараз поза дозволеним часом роботи**. На главной
панели блок **Стан реле** показывает только включённые в настройках каналы.
Если все каналы отключены, блок скрыт. Кнопка **Керування** открывает раздел реле.

| Настройка | Что делает |
|---|---|
| **AUTO** | Работает по заданным условиям и расписанию |
| **ON / OFF** | Ручной запрос включения / выключения; результат смотрите по фактическому состоянию |
| Условия запуска | Например, достаточные PV, SOC и ток заряда перед включением |
| Условия остановки | Например, слишком низкий SOC или высокая нагрузка |
| Задержка ON / OFF | Условие должно сохраняться некоторое время |
| Минимум между переключениями | Защита от частого переключения |
| Максимальная работа | Ограничение непрерывного включения; 0 отключает этот лимит |
| Cooldown / пауза | Время ожидания перед следующим запуском |
| Приоритет | Очерёдность запуска нескольких нагрузок |
| Дни и часы | Когда автоматическая работа разрешена |

Если карточка сообщает внешнее управление тарифом, обычные условия AUTO этого канала не управляют им. Меняйте режим во вкладке **Нічний тариф**. Не считайте ручное ON разрешением обходить отключённый канал или ограничения защиты.

При потере необходимых свежих измерений автоматика может отключить нагрузку. Для системы с двумя BMS отсутствие одной важно даже тогда, когда в панели ещё видны данные второй.

<a id="tariff"></a>
## 10. Ночной тариф

Это отдельное правило управления выбранным реле: ночью разрешать питание/заряд от сети по SOC, днём защищать батарею и учитывать солнечный заряд. Оно не узнаёт тарифы у поставщика электроэнергии и не меняет физическую схему подключения.

1. Откройте **Реле → Нічний тариф / Night tariff**.
2. В группе подключения выберите реле, которое сборщик выделил для этой функции.
3. Укажите начало и конец ночного окна, например 23:00–07:00 **только если это ваш действительный тариф**.
4. Задайте ночной SOC включения и более высокий SOC отключения.
5. Задайте дневной аварийный SOC включения и SOC восстановления/отключения.
6. Если нужен режим достаточного солнечного заряда, укажите пороги PV, тока и время подтверждения. Это реальные измерения, не погодный прогноз.
7. Проверьте параметр поведения при потере данных — **Fail-safe grid**. Он может запрашивать включение сети при недоступных измерениях; смысл ON зависит от проводки вашего реле.
8. Включите тарифный контроллер, нажмите **Зберегти налаштування** и выберите **AUTO**.
9. Проверьте карточки **Локальний час ESP**, **Період**, **Причина**, **Джерело SOC** и фактическое состояние реле.

**ON** и **OFF** здесь — ручные режимы тарифного контроллера. Они не совпадают с включением/выключением самой функции. После ручной проверки верните **AUTO**, если нужен автоматический режим.

Максимальное время работы и cooldown выбранного реле действуют и при управлении тарифом. Обычные пороги AUTO реле при этом не применяются. Часы ESP должны быть синхронизированы.

ESP использует восточноевропейское время с переходом на летнее/зимнее. Отдельного выбора пояса в панели нет. Если вы живёте в другом поясе, согласуйте расписание со сборщиком; смена часов телефона не меняет часы ESP.

Этот раздел настраивает физическое управление реле. Цены и часы в
**HA → Power Monitor → Аналитика → Тарифы** используются для расчёта стоимости
и не изменяют расписание или пороги реле ESP. После изменения любого из этих
двух расписаний проверьте второе отдельно, если хотите использовать одинаковые часы.

<a id="forecast"></a>
## 11. Прогноз солнечной генерации

1. Откройте **Налаштування → Прогноз генерації PV**.
2. В источнике выберите **Open-Meteo**.
3. Впишите город и нажмите **Знайти координати міста**. Выберите правильный город и страну в результатах.
4. Введите суммарную паспортную мощность панелей в **ваттах**: например, для 3 кВт укажите **3000**.
5. Укажите угол наклона: 0° — горизонтально, 90° — вертикально.
6. Укажите направление: 90° — восток, 180° — юг, 270° — запад.
7. Укажите оценку эффективности системы, согласованную со сборщиком. Если точной оценки нет, можно оставить исходное значение формы; прогноз будет приблизительным.
8. Оставьте стандартный адрес Open-Meteo, если не используете другой совместимый сервис.
9. Нажмите **Зберегти прогноз**.
10. Откройте главную страницу и дождитесь недельного прогноза; при необходимости нажмите **Оновити** в его карточке.

Запрос делает **браузер телефона или компьютера**, поэтому интернет нужен этому устройству. Прогноз не обновляется в фоне на ESP при закрытой панели и не управляет реле. Тени, снег, разные направления нескольких групп панелей и ограничения инвертора могут заметно изменить реальную генерацию.

Пункт **Власний сервер** нужен только при наличии уже подготовленного сервиса. Получите URL и токен у его администратора. Сервер должен разрешать обращения из браузера. Для отключения выберите источник **Вимкнено** и сохраните. Выключение источника не равнозначно удалению сохранённого ключа.

Условия и лимиты погодного сервиса могут меняться. Для коммерческого использования устройства проверьте подходящий тариф у поставщика API: [Open-Meteo](https://open-meteo.com/en/pricing).

<a id="backup"></a>
## 12. Резервная копия

### Сохранить настройки в файл

1. Откройте **Налаштування → Імпорт / експорт налаштувань**.
2. Отметьте нужные группы. Для полной копии текущих доступных настроек отметьте все восемь.
3. Нажмите **Експортувати файл**.
4. Найдите скачанный файл в «Загрузках» телефона/компьютера. Сохраните его в личном защищённом месте с понятной датой.

| Группа | Что переносится |
|---|---|
| Реле | Каналы и весь ночной тариф вместе |
| Telegram | Токен, получатели, подписки, пороги, отчёты |
| Home Assistant | Адрес брокера, вход и параметры интеграции |
| Профиль инвертора | Выбранный способ связи и его параметры |
| Wi-Fi | Домашняя сеть, её пароль, имя устройства |
| Прогноз PV | Местоположение, панели, источник и ключи |
| BMS | Привязка двух слотов и режим банка |
| Пароли доступа | Пароль панели и точки ESP32 |

**В файле открыто записаны пароли и токены.** Не отправляйте его в публичные чаты и не кладите в общий репозиторий. Копия не содержит прошивку, архив измерений, полный набор внутренних настроек инвертора или JK BMS.

Для HA нужна отдельная резервная копия самого Home Assistant. В неё должны
входить архив интеграции, цены аналитики, настройки команд Telegram, штатной
«Энергии» и база статистики HA. Экспорт настроек ESP эти данные не сохраняет.
Для ручного копирования остановите HA или используйте штатную согласованную
резервную копию: копия только открытого файла SQLite может быть неполной.
Сохраняйте обе базы интеграции — `archive.sqlite` и `analytics.sqlite` —
вместе с настройками HA и дашбордами.

В **карточке управления HA** экспорт имеет **9 разделов**: реле и тариф
выбираются отдельно. При импорте сначала проверяются все выбранные разделы,
затем они применяются по очереди. При ошибке часть могла уже сохраниться —
прочитайте список применённых разделов и обновите показания перед повтором.
Пустой пароль Wi-Fi не очищает действующий секрет; другая сеть без пароля
пропускается. Открытую сеть задают явно в настройках сети.
После успешного импорта формы обновляются фактическими значениями.

### Восстановить

1. Сначала экспортируйте текущие настройки, если хотите иметь возможность вернуться к ним.
2. Убедитесь, что файл предназначен для вашей установки. На другой плате номера реле, нагрузки и Bluetooth-адреса могут не соответствовать оборудованию.
3. Откройте тот же блок и нажмите **Імпортувати файл**.
4. Выберите файл. В предпросмотре проверьте и отметьте нужные группы.
5. Нажмите **Застосувати вибрані групи / Apply selected groups** или **Скасувати / Cancel** для отказа.
6. Прочитайте результат и требуется ли перезапуск. При изменении сети устройство может перезапуститься автоматически.
7. Подключитесь к восстановленной сети и войдите восстановленным паролем.
8. Проверьте показания, Telegram, HA и особенно режимы реле.

Галочки экспорта определяют состав сохраняемого файла. Для восстановления выберите группы отдельно в предпросмотре импорта. Сам выбор файла настройки не меняет.

Если импорт завершился ошибкой, часть групп уже могла примениться. Прочитайте список в сообщении и проверьте их; это не операция «всё или ничего».

Если часть настроек из файла не поддерживается, панель сообщит, что именно
пропущено. Проверьте результат перед перезапуском.

<a id="update"></a>
## 13. Перезагрузка и обновление

### Просто перезагрузить

1. Откройте **Налаштування**.
2. Нажмите кнопку перезапуска вверху страницы.
3. Нажмите появившуюся кнопку подтверждения. Для отказа есть **Скасувати / Cancel**.
4. Подождите примерно минуту и откройте панель снова.

Перезагрузка не стирает настройки. Короткое нажатие **EN/RESET** на плате тоже перезапускает её, но штатная кнопка в панели предпочтительнее: перед ней устройство сохраняет ожидающие данные истории. Кнопка **BOOT** имеет другое назначение — см. раздел 14.

### Обновить прошивку через браузер

1. Получите у сопровождающего проекта **готовый файл приложения .bin именно для вашей платы Power Monitor** и сведения о версии.
2. Сделайте резервную копию настроек. Сохраните также предыдущий проверенный файл прошивки, если он у вас есть.
3. Обеспечьте стабильное питание ESP и связь. Закройте лишние вкладки панели.
4. Откройте **Налаштування → Оновлення прошивки**.
5. Нажмите **Вибрати файл** и выберите полученный `.bin`. Не выбирайте bootloader, partition table или полный образ flash.
6. Нажмите **Оновити прошивку** один раз.
7. Дождитесь завершения загрузки, записи и сообщения о перезапуске. Не закрывайте вкладку и не отключайте питание во время записи.
8. Если запись завершилась, но перезапуск не подтверждён, следуйте сообщению панели. При доступной панели используйте её кнопку перезапуска.
9. После запуска подождите не менее минуты. Проверьте отображаемую версию, главную страницу, суточные данные, историю, BMS и интеграции.

Если обновление закончилось ошибкой, не начинайте сразу несколько повторных загрузок. Дождитесь восстановления панели, посмотрите текущую версию и сохраните текст ошибки. Успех передачи файла ещё не доказывает, что новая версия запустилась и всё работает.

Обычное обновление приложения сохраняет настройки и историю. Автоматический возврат неудачной прошивки зависит от установленного загрузчика и не гарантируется на любой ранее прошитой плате.

### Обновить ESP из Home Assistant

В **Power Monitor → Управление → Настройки → Обновление ПО** выберите
готовый app `.bin`. Проверьте показанную версию файла и подтвердите один раз.
Окно подтверждения закрывается сразу; прогресс, скорость и результат остаются
на карточке. После передачи интеграция ждёт новый запуск ESP и подтверждение
здоровой работы не менее минуты. Только затем появляется успех.
Не запускайте вторую загрузку при потере ответа: сначала проверьте текущую
версию и состояние устройства. После успешной OTA проверьте также историю,
графики и BMS — одного сообщения о записи файла недостаточно.

### Вернуться на предыдущую версию

Получите у сопровождающего **совместимый файл предыдущей прошивки** и установите
его через тот же раздел обновления. Не стирайте настройки и историю.
Если панель не открывается, поручите восстановление сборщику.

При возврате интеграции HA сохраните её архив и свой дашборд. После замены
файлов перезапустите HA и обновите страницу.

<a id="reset"></a>
## 14. Сброс и восстановление доступа

**Сброс выполняется кнопкой BOOT на уже работающей ESP.** Это не кнопка EN/RESET. Если корпус не даёт безопасного доступа, обратитесь к сборщику. Не открывайте отсек с сетевым напряжением ради кнопки.

| Действие | Что меняется | Что сохраняется |
|---|---|---|
| Перезагрузка в панели или EN/RESET | Устройство запускается заново | Настройки, записанная история |
| BOOT **3–9 секунд**, затем отпустить | Стирается название/пароль домашнего Wi-Fi; пароль ESP32 становится `inverter1234` | Пароль веб-панели, Telegram, HA, BMS, инвертор, реле, тариф, записанная история |
| BOOT **от 10 секунд**, затем отпустить | Сбрасываются пользовательские настройки ESP и сохранённые служебные состояния Telegram | Установленная прошивка, записанная история и журнал событий; внутренние настройки инвертора/BMS |

### Забыли Wi-Fi или сменили роутер: сетевой сброс

1. Включите ESP обычным образом, **не удерживая BOOT** при включении. Подождите около минуты.
2. Нажмите **BOOT** и удерживайте примерно **5 секунд**.
3. **Отпустите** кнопку до истечения 10 секунд. Сброс выполняется при отпускании.
4. Дождитесь перезапуска.
5. На телефоне подключитесь к **ESP32**, пароль **inverter1234**. Если телефон помнит другой пароль, сначала выберите «Забыть сеть».
6. Откройте **http://192.168.4.1/**.
7. Войдите как **admin** со **своим прежним паролем панели**.
8. Заново укажите домашний Wi-Fi, сохраните настройки и перезапустите ESP.
9. Если Wi-Fi-модуль инвертора подключался к ESP32, восстановите согласованный пароль AP или заново подключите модуль к ней.

### Забыли пароль панели: полный сброс

Полный сброс удаляет настройки Wi-Fi, Telegram, HA, BMS, профиля инвертора, реле, тарифа, прогноза и имя устройства. Перед ним сохраните backup, если доступ ещё есть, и обеспечьте допустимое состояние подключённых нагрузок.

1. Дайте ESP полностью запуститься, не зажимая BOOT при подаче питания.
2. Удерживайте **BOOT примерно 12 секунд**.
3. Отпустите кнопку и дождитесь перезапуска.
4. Подключитесь к **ESP32**, пароль **inverter1234**.
5. Откройте **http://192.168.4.1/**.
6. Введите логин **admin**, пароль **admin1234**.
7. Настройте устройство заново и задайте новые пароли. Либо восстановите доверенную резервную копию.
8. Перед возвратом автоматического управления проверьте назначения и режимы реле.

Если восстановите группу **Пароли доступа** из копии, вернётся пароль из этой
копии, включая забытый старый пароль. Чтобы сохранить новый пароль, снимите
галочку с этой группы в предпросмотре импорта — см. [раздел 12](#backup).

Если ESP не запускается после манипуляций: отпустите BOOT и кратко нажмите **EN/RESET**, затем подождите. Удержание BOOT во время включения может перевести плату в режим прошивки, в котором обычной панели нет.

Полный сброс **не откатывает прошивку**, **не стирает всю историю**, **не сбрасывает сам инвертор или BMS**. Для передачи устройства другому владельцу очистку оставшихся измерений и проверку скрытых старых настроек согласуйте со сборщиком.

<a id="outages"></a>
## 15. Что будет при отключениях

| Ситуация | Чего ожидать |
|---|---|
| Закрыли браузер | ESP продолжает собирать историю и выполнять свою автоматику. Прогноз в браузере не обновляется |
| Пропал интернет, домашний Wi-Fi работает | Локальная панель и локальный HA могут работать. Telegram и свежий прогноз недоступны |
| Выключился роутер | ESP пытается восстановить связь. Примерно через 5 минут без рабочего соединения появляется аварийная AP ESP32. Уже работающая сервисная AP для логгера сохраняет свою роль |
| Пропала BMS или связь с инвертором | Показания становятся недоступными; зависящая от них автоматика реагирует по своим правилам |
| Выключилась ESP | Она не измеряет, не отправляет уведомления и не управляет выходами. Состояние силовой цепи зависит от проводки и релейного модуля |
| Вернулось питание ESP | Загрузка сохранённых настроек, восстановление связи, синхронизация времени; первые показания могут появляться не одновременно |
| Перезапустился HA или брокер | Датчики могут временно стать недоступными. Повторное соединение ESP с MQTT может занимать несколько минут |
| Выключился HA, ESP работает | ESP продолжает измерения, историю, реле и свои уведомления. Команды бота, аналитика и панель HA недоступны до запуска сервера |

Пропуски измерений во время отключения не восстанавливаются задним числом. При внезапной потере питания могут не сохраниться до **13 последних минутных точек** и примерно **5 минут накопленной энергии**. Штатный перезапуск через панель уменьшает эту потерю, сохраняя ожидающие данные.

Для уведомлений Telegram с ESP нужны интернет, корректное время и достаточная
свободная память ESP. Очередь ограничена; задержки и потеря отдельных
уведомлений возможны. Для `/status` и `/pv` нужны работающий HA и интернет
на сервере. Если выключилась сама ESP, она не сможет немедленно сообщить об этом.
Power Monitor не заменяет независимую защиту аккумулятора, аварийную
сигнализацию или расчётный электросчётчик.

<a id="troubleshooting"></a>
## 16. Если что-то не работает

| Проблема | Что сделать по порядку |
|---|---|
| Не открывается pm.local | Проверить одинаковую домашнюю сеть → отключить VPN/гостевую изоляцию → попробовать IP из роутера → проверить питание ESP |
| Телефон уходит из ESP32 | Выбрать «Оставаться в сети без интернета» → временно выключить мобильные данные → вручную открыть 192.168.4.1 |
| Не подходит пароль | Убедиться, что не перепутаны Wi-Fi, AP и пароль панели → попробовать приватную вкладку → выбрать нужный вид сброса из раздела 14 |
| После сохранения ничего не изменилось | Проверить кнопку именно нужного блока → прочитать ошибку → выполнить требуемый перезапуск |
| Крутится загрузка графиков | Подождать → закрыть лишние вкладки → обновить страницу один раз. Если повторяется, записать время, адрес страницы и текст ошибки |
| BMS не найдена | Включить Bluetooth BMS → закрыть её приложение на телефоне → приблизить ESP → проверить фильтр и выбранный слот |
| BMS подключена, но показаний нет | Дождаться свежих данных → сверить модель → проверить соединение. Само слово Connected ещё не подтверждает полноценный обмен |
| Нет инвертора | Сверить точную модель и сохранённый/активный профиль → перезапустить после смены → проверить кабель либо подключение Wi-Fi-модуля к сети, указанной для выбранного профиля |
| Нет тестового Telegram | Нажать Start именно у своего бота → сверить токен и Chat ID → включить профиль и «Мережу відновлено» → сохранить/перезапустить → отправить тест |
| Telegram: Invalid token / 401 | Заново скопировать полный токен из BotFather, сохранить и перезапустить |
| Telegram: 403 | Проверить, не заблокирован ли бот пользователем и разрешено ли ему писать в нужный чат |
| MQTT не подключается | Проверить запуск брокера, IP, порт 1883, transport tcp и пользователя; 8123 и адрес ESP здесь не подходят |
| MQTT временно ждёт повтор | Подождать несколько минут. Если появилась кнопка «Повторити MQTT з активними налаштуваннями», нажать один раз; она не применяет несохранённые поля |
| MQTT Connected, но датчиков нет | Проверить интеграцию MQTT в самом HA и одинаковый discovery prefix → дождаться окончания публикации → открыть устройства именно этой интеграции |
| Прямая интеграция Power Monitor не управляет ESP | Проверить доступность ESP из HA и право администратора → выполнить «Перенастроить» с новым кодом → полностью обновить страницу |
| Power Monitor не появился после установки | Проверить путь `custom_components/power_monitor_archive/manifest.json` → перезапустить HA → обновить браузер → добавить интеграцию в «Устройства и службы» |
| После обновления остались старые карточки | Проверить версию в HACS → перезапустить HA → полностью обновить страницу или заново открыть приложение HA; архив и интеграцию не удалять |
| HACS не видит новый релиз | В меню репозитория выбрать «Обновить информацию» → проверить доступ HA к GitHub → повторно открыть страницу Power Monitor |
| Уведомления приходят, но `/status` и `/pv` молчат | Проверить, работает ли HA → бот HA должен использовать Polling или Webhooks → сверить разрешённые чат/отправителя и включить команды в Power Monitor → Telegram; тест уведомлений ESP команды HA не проверяет |
| Telegram требует перезапуск | Сохранить настройки, перезапустить ESP, затем отправить тест |
| BMS запись закончилась тайм-аутом | Обновить настройки и проверить фактическое значение; команда могла примениться, повторять вслепую нельзя |
| После обновления HA показывает прежний интерфейс | Перезапустить HA и полностью перезагрузить страницу браузера |
| Нет вкладки «Аналитика» | Открыть именно Power Monitor из бокового меню под администратором → полностью обновить страницу. Добавлять отдельную карточку вручную не требуется |
| В аналитике нет истории батареи | Проверить доступность нужной BMS → дождаться первого опроса, до 5 минут. Данные до подключения HA или от другой батареи не появятся |
| В ячейках стоит «—» | Проверить выбранную BMS, дату и связь. Это отсутствующее измерение, а не нулевое напряжение |
| Стоимость учтена не за весь период | Проверить выбранный тариф и покрытие измерениями. Для дня/ночи нужны минутные данные; одних старых суточных итогов недостаточно |
| `/status` или `/pv` молчат | Проверить работу HA → Telegram bot в HA и разрешённый чат → Управление → Telegram → Команды и графики → нужный переключатель и сохранение |
| В «Энергии» HA пусто или нет нужных датчиков | Выполнить настройку из раздела 8 → выбрать счётчики kWh → проверить Recorder и дату начала сбора |
| В «Энергии» завышены итоги | Проверить, не добавлен ли один поток дважды через MQTT и прямую интеграцию; исключить пересечение импортированного архива с текущими датчиками |
| Реле не слушается обычного AUTO | Проверить, не управляет ли им ночной тариф → посмотреть причину, расписание, задержки, cooldown, свежесть BMS/инвертора |
| Прогноз пустой | Проверить интернет на телефоне/ПК, город, мощность панелей и источник → нажать «Оновити». Для своего сервера обратиться к его администратору |
| После импорта потерян доступ | Подключиться к Wi-Fi из копии, использовать восстановленный пароль → при необходимости выполнить сетевой сброс |
| Обновление прервалось | Дождаться восстановления панели → проверить версию → сохранить ошибку → обратиться к сопровождающему, если устройство не запускается |

Для обращения за помощью подготовьте время сбоя, время работы ESP, модель
инвертора/BMS, способ связи, название вкладки и снимок ошибки. Если
сопровождающему понадобятся сведения из диагностики, скопируйте их по его
запросу. Не отправляйте токены, пароли и полный backup в общий чат.

<a id="limits"></a>
## 17. Что важно учитывать

- Основная плата проекта — ESP32-S3 с 16 МБ flash и 8 МБ OPI PSRAM. Образ не предназначен для произвольной ESP32 с другой памятью и разводкой.
- Поддерживается один выбранный канал связи с инвертором и до двух BLE BMS. Список моделей ограничен; автоматического подбора любого инвертора нет.
- Локальная панель использует украинский и английский, HA — также русский и язык HA. Адрес pm.local зависит от поддержки локального обнаружения в вашей сети; резервный доступ — по IP. Несколько устройств с одинаковым pm.local могут конфликтовать.
- Доступ по обычному HTTP предназначен для доверенной локальной сети. Не открывайте панель ESP и MQTT напрямую в интернет; удалённый доступ организуйте через уже настроенный защищённый доступ к домашней сети/HA.
- Wi-Fi и Bluetooth используют общее радио. Много одновременно открытых панелей, плохой сигнал и большие загрузки истории могут вызывать задержки. Лучше начинать проверку с одной вкладки.
- История, SOC, время работы от батареи и прогноз являются измерениями/оценками этой системы со своими пропусками и погрешностями. Они не заменяют сертифицированный учёт и аппаратную защиту.
- Прогноз работает в браузере; у него одна конфигурация массива панелей, он не моделирует отдельно все тени и разные скаты и не управляет тарифом.
- Не все параметры инвертора/BMS разрешены к записи. Сообщение о принятой операции не равно подтверждённому изменению; дождитесь результата и проверьте показание.
- Уведомления не гарантируют мгновенную или полную доставку. «Реле включено» не измеряет реальное напряжение на контактах. `Queued` означает очередь, а `sent` — успешный ответ Telegram API, а не прочтение человеком.
